## Render failure and fix — first run went 4/5

`props['sources']` must be a **list of `{name, domain}` dicts**. I authored it as a display
string («شفق نيوز · مراسلو الوكالة»). `NewsReel/scenes/Sources.tsx:102` calls
`sources.map()`, so the string threw **`TypeError: sources.map is not a function` at frame
1452** — 240 seconds into the render — and killed the slug.

**Why it hid on 4 of 5 slugs:** V11 draws its attribution from the brief's `sourcesLine` and
never mounts `Sources.tsx`. Only the one V10.1 slug could expose it. It is a latent-props
failure of exactly the class the V11 architecture makes easy to miss.

**Fixed on all five slugs, not just the control** — `render-reel.sh` auto-falls-back to V10 on
any V11 failure, so a fallback on any voiced slug would have hit the identical crash.

**Guard added** (`_validate()` in `scripts/author_2026_09_03.py`): the shape is now checked at
authoring time instead of four minutes into a render. It proved itself immediately by aborting
a re-run of the author script *before* it could overwrite the QA-patched props with pre-QA draft
copy — the script's own `SLATE` still holds the unpatched string.

This re-trigger was a **fix**, not the transient-failure retry the runbook budgets for.
