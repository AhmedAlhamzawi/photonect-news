### ⚠️ One defect shipped: slug B lost a stat pop

`render.log`: `⚠ statPop matchWord not found in VO: 'وستة عشر' — skipped` → **slug B rendered with `pops=1`, not 2.** The other three V11 slugs logged `pops=2`.

**Root cause, and it is my authoring error, not a model failure.** `scripts/build_v11_props.py:114` resolves a pop with `next(w for w in W if m in w["word"])` — it tests the matchWord against **one TTS timing word at a time**. `«وستة عشر»` is two words, so it can never match anything. My pre-flight check tested `matchWord in voText`, a substring test on the *joined* string, which passes happily for a phrase that the renderer can never resolve. The existing house rule ("matchWord must appear verbatim in voText") is true but not sufficient, and that gap is exactly what let this through.

**Not re-triggered.** The slate had already rendered, uploaded and scheduled all five posts by the time the log was read; re-running would have created duplicate scheduled posts for the whole slate to recover one on-screen number badge. The reel is otherwise complete and correct — $516M is still spoken, still in the hook headline, and still the caption's lead. Cost is one missing pop on one reel.

**Fixed for next time (component, not output):**
- `scripts/verify_slate_2026_09_06.py` now rejects any matchWord containing a space, and counts matches against `voText.split()` tokens using the renderer's own `in`-per-word semantics rather than a substring test on the joined text. It would have failed this slate before the commit.
